# Phone voice (Vapi): readiness handover

Snapshot of phone-voice webhook security, call limits and failure reporting at main
`a72fa7d`, plus the draft PRs opened on 2026-10-11. It is an input to the consolidated
release gate, not a gate decision. Verify live state before relying on any line here.

Status words: **merged** = on main; **draft** = open PR, not merged; **mocked** =
proven by unit tests with mocked providers only; **live** = observed against a real
Vapi call. Nothing in this document is live-verified.

## One Syveka alignment

Reused today: the org context from the signed assistant, the shared tool registry
(`executeTool` with a `voice_ai` identity and `enabledTools`), Business DNA in the
system prompt, plan entitlements and usage records, the workflow event bus.

Gaps (no refactor started):

- **Post-call summary.** Calls Anthropic directly with an inline prompt. It bypasses the
  model router's provider abstraction and the AI spend and usage accounting
  (`assertAiSpendAllowed` / `recordAiSpend`). Next step: route it through the same AI
  call path as chat, once the owner decides whether summaries count against AI quota.
- **Post-call contact creation.** Writes `contact` directly. It skips the contacts
  service: plan contact limit, audit, and the `contact.created` workflow event. Next
  step: call the contacts service with a system identity.
- **Voice tool executions.** Not written to the audit log (earlier P2).
